# AES-GCM Accelerator RTL

## English

Synthesizable SystemVerilog of the accelerator specified in [`doc/ht_aes_gcm_acc`](../../doc/ht_aes_gcm_acc/VLSIT_AES_GCM_ACCELERATOR_HDS.md), written under VLSIT RTL Design Rule v2. It wraps the unchanged AES core of [`rtl/ht_aes128_256`](../ht_aes128_256/README.md) and reuses `m_vlsit_afifo_top`, `m_vlsit_sfifo_top`, `m_vlsit_ahs4_top`, `m_vlsit_rst_sync` and `m_vlsit_afifo_cell_sync` from the sibling repository `VLSIT_OPEN_IP_CORE` (DEC-016). `filelist.f` lists every source in order, with paths relative to this folder and `+define+VLSIT_SYNTHESIS` for the library cells.

| Top | Use |
|---|---|
| `m_aesgcm_acc_apb_top` | APB4 CSR, PIO data path, DMA handshake, interrupt, key side-load |
| `m_aesgcm_acc_axi_top` | The same plus the AXI4 data window |

| Module | Function |
|---|---|
| `m_aesgcm_bus_dom` | BUS-domain structure: `m_aesgcm_bus_ctl` (command decode, start checks, bundles, status, interrupts, DMA conditions, context export and import), `m_aesgcm_pio`, `m_aesgcm_dma_ch` (x2), `m_aesgcm_axi_win` |
| `m_aesgcm_xing` | Crossings: `m_aesgcm_xing_bdl` (x5, FSM hsk and hsr, with `m_aesgcm_hs_xing`), `m_aesgcm_fifo_in` / `m_aesgcm_fifo_out` (with `m_aesgcm_pack` / `m_aesgcm_unpack`), synchronizers of `i_gcm_secure_only` |
| `m_aesgcm_core_dom` | CORE-domain structure: `m_aesgcm_seq` (FSM seq), `m_aesgcm_key_sel`, `m_aesgcm_fmt_in`, `m_aesgcm_fmt_out`, `m_aesgcm_ghash` (with `m_aesgcm_ghash_mul`, `m_aesgcm_hpow`), `m_aesgcm_tag`, `m_aesgcm_ctx`, AES core |
| `m_aesgcm_rst_sync` | Reset synchronizer with the test-mode override |
| `csr/` | CSR generated by APB-CSR-Generator from `aesgcm_CSR.xlsx` (do not edit, see `csr/CSR_GENERATED.md`) |

Illegal parameter values are reported by the verification-only checker `verification/ht_aes_gcm_acc/m_aesgcm_param_check.sv` (DEC-019).

Checks of 2026-11-25: `vlsit_rtl_check.py check` PASS (0 errors, `rtl_check_report.md`); Verilator lint PASS for both tops (`lint_apb_top.log`, `lint_axi_top.log`, only unused-signal warnings) and for the configurations CFG-LINK, CFG-BOOT, CFG-FULL, CFG-LEGACY, CFG-MIN, export mode, and 4 lanes with pipeline and related clocks. Smoke simulations against an independent GCM model (NIST test cases 2 and 4, AES-256 with a 96-bit tag, policy A pass 1 and pass 2, wrong tag, GMAC, legacy CTR and ECB, AXI bursts, WRAP rejection, suspend and resume around an urgent message, abort) passed in 5 configurations. They are scratch runs, not the verification deliverable; the requirement-based testbench, coverage, CDC runs and synthesis are still to do.

## Tiếng Việt

RTL SystemVerilog tổng hợp được của bộ tăng tốc đặc tả trong [`doc/ht_aes_gcm_acc`](../../doc/ht_aes_gcm_acc/VLSIT_AES_GCM_ACCELERATOR_HDS.md), viết theo VLSIT RTL Design Rule v2. Nó bao core AES không đổi của [`rtl/ht_aes128_256`](../ht_aes128_256/README.md) và tái sử dụng `m_vlsit_afifo_top`, `m_vlsit_sfifo_top`, `m_vlsit_ahs4_top`, `m_vlsit_rst_sync`, `m_vlsit_afifo_cell_sync` của repo `VLSIT_OPEN_IP_CORE` (DEC-016). `filelist.f` liệt kê mọi source theo thứ tự, đường dẫn tính từ thư mục này, có `+define+VLSIT_SYNTHESIS` cho các cell thư viện.

| Top | Dùng cho |
|---|---|
| `m_aesgcm_acc_apb_top` | CSR APB4, đường dữ liệu PIO, DMA handshake, ngắt, nạp key side-load |
| `m_aesgcm_acc_axi_top` | Như trên, thêm cửa sổ dữ liệu AXI4 |

Bảng module ở phần tiếng Anh. Giá trị parameter không hợp lệ được báo bởi checker chỉ dùng cho verification `verification/ht_aes_gcm_acc/m_aesgcm_param_check.sv` (DEC-019).

Kiểm tra ngày 2026-11-25: rule check PASS (0 lỗi); lint Verilator PASS cho hai top và 7 cấu hình; mô phỏng smoke so với mô hình GCM độc lập PASS ở 5 cấu hình. Đây là chạy thử, chưa phải testbench nghiệm thu; testbench theo yêu cầu, coverage, chạy CDC và synthesis vẫn còn phải làm.
